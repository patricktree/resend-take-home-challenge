# Review UI

Type: prototype
Status: resolved
Blocked by: 06, 08

## Question

How should the Reviewer's flow look and behave in the Review UI (a deployed React SPA, see [08](08-reviewer-surface.md))? Prototype: the Pending list, the Decided list, the review screen showing the Draft data, approve and reject (with optional reason), the error when the Draft data changed since it was loaded, and success and failure feedback.

## Comments

- From [06](06-approval-binding.md): the verdict request sends the Revision id that was loaded. Always show `REVISION_SUPERSEDED` ("the Agent changed this Draft after you opened it; your verdict was not recorded") and `REVISION_ALREADY_DECIDED` ("already approved/rejected", from `existingVerdict`), never swallow them, and offer an explicit "Reload Draft"; never reload or re-apply a verdict automatically. Disable Approve and Reject while a verdict request is in flight. The review screen shows recipients, subject and body; `from` is not part of the review.
- From [07](07-exactly-once-sending.md): after an Approval the Draft shows sending status `QUEUED`, later `SENT` (with the Resend email ID) or `FAILED` with its reason; `OUTCOME_UNKNOWN` must read as "may have been sent; check the Resend dashboard before creating a new Draft". The typed client carries the D1 bookmark from the verdict response into the next list read, so the approved Draft does not reappear; there is no UI-side hiding of decided Drafts.
- From [08](08-reviewer-surface.md): stack is React 19 + TanStack Router and Query, following cup's `apps/web-app`, calling Reviewer endpoints through a typed client. Look follows cup's simple black-and-white style and button styles (`~/workspace/cup/apps/web-app/src/app/design-system/button.tsx`, `global-styles.ts`, `dialog.tsx`, `toast.tsx`); text inputs and textareas (rejection reason) do not copy cup's `design-system/input.tsx` and get a simple style consistent with the buttons. Screens: Pending list, Decided list (review and sending status, newest first, so failed Sends stay visible), and a Draft page reachable by URL (the Agent's `reviewUrl` points to it); unsubmitted Drafts are never shown. "Accessible" in the challenge means reachable at a deployed URL without setup; no WCAG level is required.
- From [09](09-api-surface.md): one API for everyone; the Review UI uses the same typed client as the CLI and MCP server. Pending list: `GET /api/v1/drafts?reviewStatus=PENDING&orderBy=updatedAt&order=asc` (longest-waiting first); Decided list: `?reviewStatus=APPROVED&reviewStatus=REJECTED` (default `updatedAt` desc); cursor paging (`limit` default 50). List items and verdict responses are body-less Draft summaries; the review screen loads `GET /api/v1/drafts/{draftId}` for the body (`latestRevision.body.plainText`). The API does return unsubmitted Drafts to the Reviewer, so the UI never queries them in lists, and a Draft opened by URL before submission shows "Not submitted for review yet" with no verdict buttons. Rejection reason: optional, 1–2000 characters, trimmed. Errors use `{ error: { code, message, requestId, existingVerdict? } }`; `revisionNumber` can label "Revision 3".
- From [10](10-agent-reviewer-separation.md): no login form and no cookies. On first visit (or after a 401) the SPA shows a one-field "Reviewer token" screen. A token starting with `agent_` is rejected client-side ("this is an Agent token"). The token is stored in `localStorage` and sent as `Authorization: Bearer …` by the typed client. A visible "Sign out" clears it, and any 401 clears it and returns to the token screen, keeping the requested URL so a `reviewUrl` deep link still lands on its Draft. A 403 `REVIEWER_ONLY` on a verdict (wrong token stored) is shown, not swallowed. Subject and body render only as React-escaped text, never as HTML. Under a strict CSP (`script-src 'self'`, no inline scripts), so the build must not inject inline scripts or styles that need `unsafe-inline` (check how cup's style setup in `global-styles.ts` is emitted). The Reviewer token is never hard-coded into the bundle.
- From [11](11-cloudflare-app-structure.md): the SPA is served under **`/app`** (Vite `base: "/app/"`, TanStack Router `basepath: "/app"`); `/` redirects to `/app/`, and `reviewUrl` is `https://resend-challenge.patricktree.me/app/drafts/{draftId}`. Unknown `/app/*` paths get `index.html`, so the Draft page must handle an unknown Draft id itself (the API's 404 `DRAFT_NOT_FOUND`). The package is `apps/review-ui`. `pnpm seed` creates Pending, Rejected and Approved Drafts locally, which the prototype can use.

## Answer

Settled without a prototype: the repository owner declined one and delegated every look-and-behaviour choice with "keep it simple; it is a take-home challenge, no good UX required". Everything below is the simplest option that honours the Comments above; nothing beyond them was added for polish.

- **Routes** (TanStack Router, `basepath: "/app"`): `/app/` is the Pending list, `/app/decided` the Decided list, `/app/drafts/$draftId` the Draft page. One header on every screen: links "Pending" and "Decided", and a "Sign out" button. No master-detail split, no tabs, no counts in the header.
- **Token screen**: without a stored token, the app renders the token screen _in place of_ the requested route, so the URL stays as it is and a `reviewUrl` deep link lands on its Draft once a token is entered (no redirect, no return-URL parameter). One password-type input labelled "Reviewer token" and a "Continue" button. A value starting with `agent_` is refused client-side with "This is an Agent token. Enter the Reviewer token." The token is not checked against the API up front: it is stored in `localStorage` and the route's query runs; any 401 clears the token and the query cache and shows the token screen again with "The token was not accepted." "Sign out" clears the token and the query cache.
- **Lists**: a plain table, whole row links to the Draft page. Pending columns: Subject, To (first recipient, then "+N"), Revision ("Rev. 3"), Submitted (`latestRevision.submittedAt`). Decided columns: Subject, To, Revision, Verdict ("Approved"/"Rejected"), Sending (status label, see below), Decided (`latestRevision.decidedAt`). Queries exactly as in the 09 comment. Paging: a "Load more" button while the response has a next cursor (`useInfiniteQuery`). Empty states are one line of text: "No Pending Drafts." / "No Decided Drafts." No list polling; TanStack Query's default refetch on window focus is the only refresh.
- **Times**: absolute local time via `toLocaleString()`, no relative times.
- **Draft page**: loading shows "Loading…"; 404 `DRAFT_NOT_FOUND` shows "Draft not found."; other load errors show the error `message` and `requestId`. Otherwise, top to bottom: subject as heading, "To:" with all recipients comma-separated, "Revision N", review status, submitted time; then the body as React-escaped text in a block with `white-space: pre-wrap`. If `lastVerdict` is a Rejection of an earlier Revision, one line above the body: "Revision N was rejected: \<reason>" (or without the reason). `from` is not shown.
- **By review status**: `UNSUBMITTED` shows "Not submitted for review yet." and no controls. `PENDING` shows the verdict controls. `APPROVED` / `REJECTED` show the verdict line ("Approved" or "Rejected: \<reason>", with decided time) and, for an Approval, the sending status.
- **Verdict controls** (only for `PENDING`): an "Approve" button (contained), an optional "Reason for rejection" textarea (`maxLength` 2000; trimmed, empty means absent) and a "Reject" button (outlined). No confirmation dialog for either. Both buttons are disabled while a verdict request is in flight. The control state is keyed by the loaded Revision id, so it resets when a different Revision is shown.
- **After a successful verdict**: stay on the Draft page. The mutation invalidates the Draft and both lists, so the page re-renders from the refetched Draft with the verdict line and sending status. No toast, no "next Draft" button, no navigation.
- **Sending status** (the page polls `GET /api/v1/drafts/{draftId}` every 3 s while the status is `QUEUED`, and stops otherwise; same labels in the Decided list without polling):
  - `NOT_SENT`: "Not sent".
  - `QUEUED`: "Sending…".
  - `SENT`: "Sent (Resend email ID `re_…`)".
  - `FAILED` / `REJECTED_BY_RESEND`: "Failed: Resend rejected the email, so it was not sent (\<resendErrorName>: \<resendErrorMessage>)".
  - `FAILED` / `OUTCOME_UNKNOWN`: "Failed: may have been sent; check the Resend dashboard before creating a new Draft."
- **Verdict errors**: shown inline in a bordered box directly above the verdict controls, never as a toast, never swallowed, never retried or re-applied.
  - 409 `REVISION_SUPERSEDED`: "The Agent changed this Draft after you opened it; your verdict was not recorded." plus a "Reload Draft" button.
  - 409 `REVISION_ALREADY_DECIDED`: "This Revision was already approved." / "…already rejected." (from `existingVerdict`) plus "Reload Draft".
  - 403 `REVIEWER_ONLY`: "The stored token is not the Reviewer token. Sign out and enter the Reviewer token."
  - Any other error (including `REVISION_NOT_SUBMITTED`, network failures): its `message` and `requestId`.
  - "Reload Draft" refetches the Draft and clears the error; the Reviewer then decides again on whatever is current.
- **Style**: cup's black-and-white look: its CSS reset and base variables, `DSButton` (variants `contained` and `outlined`), Inter via `@fontsource`. The textarea and token input get a 1 px `currentcolor` border with the button's border radius and padding. Tables get a 1 px bottom border per row. Content sits in one centred column (max width about 960 px). Not used: cup's `dialog.tsx`, `toast.tsx`, `input.tsx`, keyboard shortcuts.
- **CSP compatibility** (the open check from 10): cup's `app-styles.tsx` injects its reset and base CSS with `<style dangerouslySetInnerHTML>`, which the SPA's CSP blocks (`default-src 'self'` with no `style-src`, so inline `<style>` elements are refused). The Review UI therefore must not copy that component: it ships the reset and base styles as a global stylesheet that Vite emits as a file (a plain imported `.css` file, or Linaria `:global()` extracted by wyw-in-js). Linaria `css` blocks are extracted to static CSS at build time and are fine, as are fonts bundled by `@fontsource` (`font-src` falls back to `'self'`). React `style` props are set through the CSSOM and are not affected by the CSP.
