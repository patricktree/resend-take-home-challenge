## Environment setup

On a fresh checkout or worktree:

```sh
git submodule update --init --recursive
source ~/.nvm/nvm.sh && nvm install
corepack enable
pnpm install
cp apps/cloudflare-worker/.dev.vars.example apps/cloudflare-worker/.dev.vars
```

The `.patricktree-stack` submodule holds the shared configs; if it is missing, `pnpm install` initializes it and fails once, so retry. `pnpm install` also generates the Worker types (`worker-configuration.d.ts`, not committed); run `pnpm cf-typegen` after changing a Wrangler config. `.dev.vars` (gitignored) is only needed for `pnpm dev`; tests never read it.

`pnpm dev` applies the local D1 migrations and starts Vite with the Worker and the Review UI (<http://localhost:5173/app/>, hot reload). Locally, call the API with `LOCAL_AGENT_TOKEN` or `LOCAL_REVIEWER_TOKEN` from `libs/api.routes/src/local-tokens.ts`. With `pnpm dev` running, `pnpm seed` (`tooling/seed`) creates Pending, Rejected and Approved Drafts through the typed client; it calls `http://localhost:5173` unless given `--base-url` or `DRAFT_APPROVAL_BASE_URL`.

## Validation

| Command                  | Runs                                                                                                 | Needs                          |
| ------------------------ | ---------------------------------------------------------------------------------------------------- | ------------------------------ |
| `pnpm validate:fast`     | Format check, markdownlint, Knip, build and typecheck, lint, unit, integration and CLI process tests | Nothing beyond the setup above |
| `pnpm validate:extended` | Builds the Worker and runs the e2e tests (`qa/e2e`) with Playwright's browsers in Docker             | Docker with host networking    |

Run `pnpm validate:fast` before every commit and both before opening a pull request. After an intended visual change, `pnpm validate:update-snapshots` (`validate:fast`, then the e2e tests with `--update-snapshots=changed`; `pnpm test:e2e:update` runs only the latter) rewrites the screenshot baselines in `qa/e2e/snapshots/`; review and commit them. Use `pnpm fix` to apply formatting and autofixable lint findings. There are no Git hooks.

`pnpm test:resend-live` (in `qa/resend-stub/test-live/`, its own Vitest config) is the opt-in contract test that checks the Resend stub's idempotency model against the real API. It needs `RESEND_API_KEY` (`RESEND_FROM` defaults to the one in `wrangler.jsonc`) and sends real emails to `delivered@resend.dev`, so it is part of no validation command and only Patrick runs it.

## Conventions

- Work test-first: a failing test, then the code that makes it pass. Integration tests come first, through the `useWorker()` fixture in `apps/cloudflare-worker/test/use-worker.ts` (one Worker per test, concurrent within a file, migrations applied, empty storage).
- Race tests that need a deterministic interleaving live in the drafts suite (`libs/drafts/test/`): `useBindings()` gives each test fresh D1 and R2 bindings in Wrangler's local test runtime, and `createGatedD1Database()` wraps `DB` so a test holds a chosen statement or batch (`holdNext()`, then `release()`) while another use case commits. A held call also reveals its SQL, which `libs/drafts/test/list-drafts.test.ts` and `libs/drafts/test/send-reconciler.test.ts` run through `EXPLAIN QUERY PLAN` to pin their index use. The Approval and the Send reconciler (`reconcileSends()`) take the Send Queue as a parameter, so drafts tests pass `createRecordingSendQueue()` or `createFailingSendQueue()` (`libs/drafts/test/recording-send-queue.ts`), which cover both `send()` and `sendBatch()`. Production code has no test hooks.
- A query meant to use a partial index must spell out the index's `WHERE` terms with literal values (see `IS_QUEUED` in `libs/drafts/src/send-reconciler.ts`): SQLite does not match a bound parameter, such as the one `eq()` binds, against a partial index's `WHERE`.
- Integration tests count Send Queue messages with `readSentSendQueueMessages(worker)`, or every `send()` and `sendBatch()` call with `readSendQueueCalls(worker)`: the test entry point `apps/cloudflare-worker/test/worker.ts` wraps `SEND_QUEUE` in a recording double before delegating to the production `fetch` and `scheduled`, and exposes the recording as an RPC method, not a route. `runCronTick(worker)` runs one tick of the Send reconciler through `worker.scheduled()`; tests backdate `approved_at`, `deadline` and `enqueued_at` through `worker.getEnv().DB` rather than faking the clock.
- Send pipeline tests (`send-pipeline.test.ts`, `send-reconciler.test.ts`, `send-dlq.test.ts` and `send-outcome-races.test.ts` in `apps/cloudflare-worker/test/`) send through a per-test Resend stub, usually set up with `useSendPipeline()` and `createApprovedDraft()` from `test/use-send-pipeline.ts`: `useResendStub()` in `test/use-resend-stub.ts` starts `@draft-approval/resend-stub` (`qa/resend-stub`, a `node:http` server that models Resend's idempotency and takes scripted answers, hangs and held requests), and `useWorker(context, resendStubWorkerOptions(resendStub.url))` points `RESEND_BASE_URL` at it with a dummy `RESEND_API_KEY`. Each scenario delivers its batch with `deliverSendQueueBatch(worker, messages)`, which calls the test-only route `POST /__test/queue` of `test/worker.ts` (the real `queue()` handler on a hand-built `MessageBatch`) and returns each message's ack, retry and `delaySeconds`; `deliverSendDlqBatch(worker, messages)` does the same for the DLQ consumer through `POST /__test/dlq`. Assert "exactly once" in every scenario with `expectExactlyOneEmailPerSentDraft(worker, resendStub)`. Only one test uses real Miniflare delivery (`useWorker(…, { shouldConsumeSendQueue: true })`, the `send-queue-delivery` environment of `test/wrangler.test.jsonc`); the default test environment has no Queue consumer, so nothing races the route.
- Inside a D1 `batch()`, Drizzle maps a joined select by column name, so columns both tables have (such as `id`) overwrite each other; batch single-table selects instead (see `libs/drafts/src/get-draft.ts`).
- Fix the underlying cause of every lint, type or test failure; lint rules, type checks and tests stay enabled, with no disable comments, `@ts-expect-error`, skipped tests or Knip ignores for real findings.
- "Harness" means an agent harness only; call a test setup a test runtime, fixture or test setup.
- Tests start their own servers on OS-assigned ports and never attach to a running server. Vitest runs with `retry: 0`.
- Every package whose tests run its code in Vitest's own process has `test:coverage` (`vitest run --coverage`). `apps/cloudflare-worker` and `apps/cli` have none: the Worker's code runs inside workerd and the CLI's in spawned processes, where Vitest's V8 coverage sees nothing.
- Mark every new kind of committed generated file `linguist-generated=true` in `.gitattributes`, so pull request diffs and agent reviews (`git diff -- . ':(exclude,attr:linguist-generated=true)'`) leave it out. The OpenAPI snapshot (`apps/cloudflare-worker/test/__snapshots__/openapi.json`) is one; regenerate it with `pnpm --filter '@draft-approval/cloudflare-worker' test -u` rather than editing it.
- D1 migrations live in `libs/drafts/migrations/`; every Wrangler config points `migrations_dir` there. They are generated from the Drizzle schema in `libs/drafts/src/schema.ts`: after changing it, run `pnpm --filter '@draft-approval/drafts' migrations:generate --name <change>` and commit the new SQL file with the updated `meta/` files; never edit a generated migration.
- Clients of the API use the typed client `DraftApprovalClient` from `libs/api.client`; it keeps and resends the read bookmark and throws `ApiError` for error responses.
- The MCP server lives in two places: `libs/mcp-server` holds the six tools on the typed client, and `libs/api.server/src/mcp-endpoint.ts` mounts them at `/mcp` (stateless `createMcpHandler` from `agents/mcp/server`, Agent token only). Each request builds a `DraftApprovalClient` with the caller's token whose `fetch` calls the Hono app in-process, so tool calls pass the API's own checks. Tests drive `/mcp` with the official MCP SDK client (`apps/cloudflare-worker/test/mcp.test.ts`).
- `agents` and the MCP SDK packages sit in the `mcp` catalog of `pnpm-workspace.yaml`: `agents` names exact versions of `@modelcontextprotocol/server` and `@modelcontextprotocol/client` as peer dependencies, so upgrade the three together. `libs/api.server` lists `@modelcontextprotocol/client`, `@modelcontextprotocol/server` and `zod` only to provide those peers (pnpm installs no peers on its own here); its code imports none of them.
- The Review UI (`apps/review-ui`) is a React SPA with TanStack Router (code-based routes, `basepath: "/app"`) and TanStack Query (suspense queries), styled with cup's reset and base variables in `src/global.css` and Linaria. It calls the API only through `DraftApprovalClient` (`src/api-client.ts`) with the token stored in `localStorage`; any 401 clears the token and the query cache (`src/query-client.ts`). Global styles stay in emitted stylesheets: the Content-Security-Policy blocks inline `<style>` and scripts.
- Vite builds the Review UI with `base: "/app/"` into `apps/review-ui/dist/web/app/`, and the Worker's Vite build ships `dist/web` as its static assets. `libs/api.server/src/review-ui.ts` serves `/app` from the `ASSETS` binding, falls back to `/app/index.html`, and sets the security headers. The integration tests serve a small fixture instead (`apps/cloudflare-worker/test/assets/`). In `pnpm dev`, `apps/cloudflare-worker/vite.config.ts` merges the Review UI's Vite config and bridges two dev-server gaps: it serves `/app/index.html` and allows inline scripts and styles in the CSP.
- The e2e tests (`qa/e2e`, `pnpm validate:extended`) run Playwright's browsers in a Playwright Server in Docker (`@patricktree-stack/config-playwright`). The `reviewEnvironment` fixture (`qa/e2e/test-e2e/fixtures.ts`) starts one `wrangler dev` per test (`qa/e2e/wrangler.jsonc`: the Worker's source entry and its built assets) on a port the OS assigns, with a temporary `--persist-to` directory; the browser reaches it as `host.docker.internal`, where the local tokens are accepted. Tests seed Drafts and play the Agent's moves through the typed client, locate elements by role and accessible name (the password input by its label), wait on visible state and never retry. The fixture also starts one Resend stub per test on the host and passes its URL and a dummy `RESEND_API_KEY` to `wrangler dev` (`--var`), so Sends run through real Miniflare Queue delivery to `reviewEnvironment.resendStub`; `reviewEnvironment.executeSql()` runs `wrangler d1 execute --local` on the test's database for states no request reaches in a test, such as `OUTCOME_UNKNOWN`. `test-e2e/screenshots.test.ts` holds the five screenshot baselines (exact pixel match): it pins the per-run timestamps and Resend email id in the API responses with `page.route`, so only a UI change alters them.
- The Review UI's unit tests (`apps/review-ui/test/`, Vitest) cover its pure functions, such as the sending-status labels.
- The Agent CLI lives in `apps/cli` and runs as `pnpm draft-approval …` from the repository root. Its process tests in `apps/cli/test/` spawn the real CLI against a `node:http` API stub (`useApiStub()` in `apps/cli/test/api-stub.ts`) and pass it its whole environment, so `DRAFT_APPROVAL_TOKEN` and `DRAFT_APPROVAL_API_URL` never leak in. Its fallback token `PUBLIC_AGENT_TOKEN` and production URL in `apps/cli/src/production.ts` must equal `AGENT_TOKEN` and `PUBLIC_BASE_URL` in `wrangler.jsonc`; `pnpm secrets:generate` rewrites the token in `wrangler.jsonc`, `apps/cli/src/production.ts` and every occurrence in `README.md`, and refuses to run when the README or `production.ts` does not hold the current token.
- `apps/cloudflare-worker/wrangler.jsonc` is the production config and the one `pnpm dev` uses; `apps/cloudflare-worker/test/wrangler-config.test.ts` pins the settings the spec prescribes. Its resources come from `terraform/` (providers pinned, lock file committed). After changing `terraform/`, run `terraform -chdir=terraform fmt` and `terraform -chdir=terraform init -backend=false && terraform -chdir=terraform validate`; they need Terraform 1.10 or newer and are not part of `pnpm validate:fast`.
- The README's [Human steps](README.md#human-steps) are the deploy procedure; `pnpm secrets:generate` belongs to them, since it sets a production secret.
- Never deploy or touch real Cloudflare or Resend resources (`wrangler deploy`, `wrangler login`, `wrangler secret put`, `wrangler d1 migrations apply --remote`, `pnpm secrets:generate`, `terraform init` with the real backend, `terraform apply`) unless Patrick asks.
