# e2e tests

- The e2e tests (`pnpm validate:extended`) run Playwright's browsers in a Playwright Server in Docker (`@patricktree-stack/config-playwright`).
- The `reviewEnvironment` fixture (`test-e2e/fixtures.ts`) starts one `wrangler dev` per test (`wrangler.jsonc`: the Worker's source entry and its built assets) on a port the OS assigns, with a temporary `--persist-to` directory; the browser reaches it as `host.docker.internal`, where the local tokens are accepted. The fixture also starts one Resend stub per test on the host and passes its URL and a dummy `RESEND_API_KEY` to `wrangler dev` (`--var`), so Sends run through real Miniflare Queue delivery to `reviewEnvironment.resendStub`; `reviewEnvironment.executeSql()` runs `wrangler d1 execute --local` on the test's database for states no request reaches in a test, such as `OUTCOME_UNKNOWN`.
- Tests seed Drafts and play the Agent's moves through the typed client, locate elements by role and accessible name (the password input by its label), wait on visible state and never retry. Tests that need stale data install Playwright's clock (`page.clock`) and fast-forward it, since the Review UI's suspense queries count as fresh for 1 s.
- `test-e2e/screenshots.test.ts` holds the five screenshot baselines (exact pixel match): it pins the per-run timestamps and Resend email id in the API responses with `page.route`, and freezes `Date` for the Pending list (`page.clock.setFixedTime`) so its refresh countdown holds still; only a UI change alters them. The root [`AGENTS.md`](../../AGENTS.md#validation) describes how to update them.
